\begin{abstract}
Deploying sequence-modeling neural networks on deeply embedded hardware (TinyML) remains a formidable challenge \cite{ji2020tinyml, gao2021tinytl}. The primary bottlenecks are the strict Static Random-Access Memory (SRAM) constraints of microcontrollers and the irregular sampling rates (temporal jitter) inherent to physical sensors. Traditional Recurrent Neural Networks (RNNs), such as LSTM \cite{hochreiter1997long} and GRU \cite{cho2014learning} architectures, assume discrete and synchronous time steps. Furthermore, they are typically deployed via schema-heavy execution frameworks that incur significant dynamic memory overhead. 

In this paper, we present an end-to-end systems-engineering pipeline for the native, bare-metal deployment of Closed-form Continuous-time (CfC) neural networks on highly constrained hardware (ESP32-S3). By utilizing a custom Execute-in-Place (XIP) parameter mapping architecture (\texttt{.omnibit}) that eliminates SRAM copies of network weights, we bypass traditional framework overhead. Our empirical evaluation against standard LSTM and GRU deployments demonstrates resilience to sensor jitter on a Processor-in-the-Loop (PiL) Inverted Pendulum dataset, mathematical parity with full-precision (FP32) PyTorch models ($MSE < 10^{-6}$), lower inference latency, and a reduced SRAM and energy footprint. All pipelines and the C++ inference engine are open-sourced for reproducibility\footnote{Source code and hardware exporter available at: \url{https://github.com/mrmyms/Omnitrain}}.
\end{abstract}

\section{Introduction}
The proliferation of autonomous edge robotics has driven a demand for localized, low-latency artificial intelligence. Processing time-series data locally on microcontrollers (MCUs) ensures deterministic response times, preserves privacy, and reduces dependency on high-bandwidth cloud infrastructure. However, state-of-the-art kinematic sequence models are fundamentally misaligned with embedded hardware.

First, standard discrete-time models, such as Long Short-Term Memory (LSTM) and Gated Recurrent Units (GRU), experience significant degradation in predictive generalization when exposed to irregular sampling intervals. Real-world sensors suffer from packet loss and varying clock frequencies, introducing severe temporal jitter. While approaches like Phased LSTM \cite{neil2016phased} or Neural CDEs \cite{kidger2020neural} address temporal irregularities, they remain computationally heavy. 

Second, the structural execution of these models relies on generalized inference engines (e.g., TensorFlow Lite for Microcontrollers). These frameworks utilize dynamic memory arenas that consume substantial portions of the restricted SRAM available on MCUs. Furthermore, heavy memory access patterns increase dynamic power consumption.

In this work, we bring Closed-form Continuous-time (CfC) architectures \cite{hasani2022closed} to bare-metal execution environments through a novel deployment pipeline. Rather than proposing a new neural architecture, our specific systems-engineering contributions are:
\begin{itemize}
    \item A custom continuous-time ODE solver optimized natively for Xtensa architectures.
    \item An Execute-in-Place (XIP) Tensor Mapping architecture (\texttt{.omnibit}) that maps Flash memory directly to the CPU cache, bypassing SRAM allocation for network parameters.
    \item Extensive benchmarking proving that CfCs execute faster, consume less energy, and provide superior robustness to sensor degradation compared to equivalent LSTMs and GRUs.
\end{itemize}

\section{Background and Related Work}

\subsection{Continuous-Time Neural Networks}
Building upon foundational continuous-time models such as Neural ODEs \cite{chen2018neural, rubanova2019latent}, Liquid Time-Constant (LTC) networks \cite{hasani2020liquid}, inspired by the nervous system of the \textit{C. elegans} nematode \cite{lechner2020neural}, introduced continuous-time dynamics to artificial recurrent networks. More recently, Hasani et al. developed a highly efficient closed-form approximation (CfC) \cite{hasani2022closed}. Despite their theoretical efficiency, their practical execution characteristics on deeply embedded hardware have remained underexplored.

\subsection{Embedded ML and Memory Bottlenecks}
TinyML research \cite{warden2020tinyml} largely focuses on reducing model size through Quantization (e.g., INT8). While highly effective at reducing Flash requirements, we hypothesize that INT8 quantization degrades the dynamic range required for differential equations. Furthermore, our architecture avoids generalized inference engines entirely. While Hardware-Aware Neural Architecture Search (HW-NAS) \cite{cai2018proxylessnas} and ahead-of-time (AOT) compilation frameworks like microTVM or TinyEngine (MCUNet \cite{lin2020mcunet}) improve execution speed, they still lack native ODE solver primitives. Alternative continuous-time approaches, such as Spiking Neural Networks (SNNs) \cite{roy2019towards}, require specialized neuromorphic hardware. A critical limitation of standard discrete frameworks like TFLite Micro \cite{david2021tflitemicro} is that attempting to deploy continuous-time ODEs on such frameworks forces the mathematical kernel to be decomposed into discrete scalar operations, resulting in catastrophic computational overhead and an explosion in dynamic memory allocation \cite{banbury2021mlperf}. Our approach implements a static memory map to achieve Execute-in-Place (XIP) parameter mapping, drastically reducing the active SRAM footprint. This memory efficiency allows us to retain full 32-bit floating-point (FP32) precision without exhausting device memory.

\section{Methodology: The OmniEngine Architecture}

\subsection{The CfC Mathematical Kernel}
To natively handle irregular sampling rates, we implement the original Closed-form Continuous-time (CfC) mathematical formulation defined by Hasani et al. \cite{hasani2022closed}. The continuous-time dynamics of the hidden state $x(t)$ given input $I(t)$ are governed by the Liquid Time-Constant (LTC) differential equation:
\begin{equation}
\frac{dx(t)}{dt} = -\left[\frac{1}{\tau} + f(x(t), I(t); \theta_f)\right] x(t) + A f(x(t), I(t); \theta_f)
\label{eq:ltc_ode}
\end{equation}
where $x(t)$ represents the hidden state vector at time $t$, $I(t)$ is the external input feature vector, and $\tau$ denotes the system's baseline time-constant vector. The function $f(\cdot)$ is a non-linear neural network parameterized by $\theta_f$, acting as a dynamic decay and state transition function, while $A$ is a learned parameter vector determining the steady-state bias.

By approximating the time-decay integral, the exact closed-form state update over an irregular physical interval $\Delta t$ is derived as:
\begin{equation}
x(t) = x(t-\Delta t) \odot \left(1 - f(x(t-\Delta t), I(t); \theta_t)\right) + g(x(t-\Delta t), I(t); \theta_g) \odot f(x(t-\Delta t), I(t); \theta_t)
\label{eq:cfc_update}
\end{equation}
where $g(\cdot)$ represents the state neural network backbone parameterized by $\theta_g$ (generating the candidate hidden state), and $f(\cdot)$ represents the time-gate network parameterized by $\theta_t$. Crucially, to ensure Equation (\ref{eq:cfc_update}) functions as a valid convex combination (mixing coefficient), the output of $f(\cdot)$ is strictly bounded in $(0, 1)$ via a Sigmoid activation function. While the Sigmoid gate reduces sensitivity to extreme values of $\Delta t$ during forward-pass inference (preventing explosive states), the training objective remains susceptible to vanishing gradients if the time-gate saturates. This is empirically mitigated via proper weight initialization and adaptive learning rates (AdamW). The variable $\Delta t$ is the explicit physical time elapsed since the last sensor sampling event. The operator $\odot$ denotes the element-wise Hadamard product. In this formulation, the time-gate $f(\cdot)$ dynamically scales the state transition based on the explicitly passed physical time delta $\Delta t$, mathematically balancing the decay of the past state with the incorporation of new sensory information.

\subsection{XIP Tensor Mapping and Cache Optimization}
To eliminate framework overhead, we introduce the \texttt{.omnibit} format. To enable this architecture, we developed a Python-based compilation toolchain that extracts the PyTorch \texttt{state\_dict}, serializes the floating-point tensors deterministically, and directly outputs the \texttt{.omnibit} binary payload ready for flashing to ROM. Utilizing SPI Flash Memory Mapping (\texttt{mmap}), the embedded C++ execution engine performs matrix multiplications by fetching weights directly from the Read-Only Memory (ROM) via the hardware data cache.

Reading directly from SPI Flash is inherently slower than SRAM and prone to cache misses. However, the \texttt{.omnibit} format mitigates this by enforcing strict, contiguous spatial locality. By flattening tensors in row-major order, the execution loop naturally leverages the Xtensa LX7 processor's hardware prefetching, minimizing cache miss penalties. The structural memory layout of the payload is detailed in Table \ref{tab:omnibit_layout}. Furthermore, the stark architectural contrast between standard framework allocation and our Zero-Copy approach is illustrated in Figure \ref{fig:zerocopy}.

\section{Experimental Setup}

\subsection{Hardware and Energy Measurement}
Experiments were conducted on an Espressif ESP32-S3 microcontroller (Dual-Core 32-bit Xtensa LX7, 512KB SRAM). The hardware was prototyped on a standard solderless breadboard. Remarkably, despite the suboptimal signal integrity and parasitic capacitance inherent to breadboard circuits, the \texttt{.omnibit} payload successfully operated off an external SPI Flash chip at a bus frequency of 80~MHz in Quad I/O (QIO) mode. While the system demonstrated functional viability on a breadboard, we caution that the \texttt{.omnibit} format demands controlled PCB routing in production to prevent EMI and signal integrity penalties. To evaluate true energy efficiency, the steady-state system current draw (encompassing both the MCU core and the active SPI Flash chip) was continuously monitored using an INA219 precision power monitor sampled at 1~kHz, while microsecond-level dynamic power transients were captured using a Digital Storage Oscilloscope (DSO) measuring voltage across a low-tolerance shunt resistor.

\subsection{Dataset and Task Definition}
\subsection{Dataset and Task Definition}
The evaluation utilizes a Processor-in-the-Loop (PiL) Inverted Pendulum (CartPole) \cite{barto1983neuronlike} physics simulation. While classical linear control techniques, such as the Linear Quadratic Regulator (LQR) \cite{astrom2010feedback}, provide optimal control with negligible memory overhead for this specific linearized task, we employ CartPole strictly as a foundational benchmarking environment. This explicitly isolates the evaluation of temporal robustness from other confounding factors like extreme non-linearities or unobservable states. However, to demonstrate that continuous-time models generalize beyond this idealized stepping stone, we subject the network to unmodeled non-linear friction and sensor degradation in Section \ref{sec:generalization}. In this task, neural predictions (forces) must be generated sequentially based on the physical state (position, velocity, angle, angular velocity). The simulation's baseline control loop operates at 50~Hz ($\Delta t = 0.02$~s), and recurrent models are trained and evaluated on sequence lengths of 5,000 steps to capture long-term dependency dynamics. The simulated trajectories were strictly partitioned into a 70\% training, 15\% validation, and 15\% testing split to prevent data leakage. Sensor inputs are z-score normalized (mean subtraction and standard-deviation scaling) using statistics computed over the training set. Crucially, all models were trained exclusively on clean, contiguous data (0\% loss). To rigorously test temporal extrapolation under distributional shift, the testing telemetry streams were artificially masked with $0\%$, $20\%$, and $60\%$ random packet loss. During a packet drop event, the input signal $I(t)$ is maintained using a Zero-Order Hold (ZOH) mechanism, persisting the last known valid sensor state until the next successful transmission.

\subsection{Baselines and Training Protocol}
The baseline comparison utilizes a Time-Aware LSTM (4,120 parameters), a Time-Aware GRU (3,980 parameters), and our CfC (4,050 parameters). To ensure reproducibility, the architectural dimensions for all models were standardized to an input feature vector $d_{in} = 5$ (physical state plus explicitly concatenated $\Delta t$), a hidden state representation $d_{model} = 32$, and an output control prediction $d_{out} = 1$. The CfC specifically utilized a multi-layer perceptron backbone with $d_{backbone} = 64$. To ensure a rigorous comparison, the discrete RNN baselines explicitly receive the elapsed time $\Delta t$ concatenated to the input feature vector $I(t)$ to mitigate temporal misalignment. The discrete RNN baselines are deployed via TensorFlow Lite for Microcontrollers (TFLite Micro) \cite{david2021tflitemicro}, which represents the industry standard for edge execution. All models were trained in PyTorch and evaluated across 30 distinct random seeds to report the mean and standard deviation ($\pm \sigma$) of the Mean Squared Error (MSE) on predictive accuracy. The pre-training phase was accelerated locally on an NVIDIA RTX 5070 GPU. The optimization utilized AdamW \cite{kingma2014adam, loshchilov2017decoupled} (learning rate $1\times10^{-3}$, batch size 1) for 250 epochs, employing Huber Loss (Smooth $L_1$) to mitigate outliers\footnote{Software stack: PyTorch 2.2.0, CUDA 12.1, NumPy 1.24.3, Arduino ESP32 Core 2.0.11 (PlatformIO \texttt{espressif32}). A Docker container is provided in the repository to guarantee bit-exact reproducibility of the \texttt{.omnibit} payload across host operating systems.}.

\section{Results and Evaluation}

\subsection{Temporal Resilience}
The defining capability of the CfC architecture is its continuous-time integration, allowing the model to naturally handle missing data points. When evaluated on the closed-loop control task, the primary performance metric is the Time-to-Failure (TTF) before the pendulum angle or cart position exceeds safety thresholds (maximum 500 steps). When subjected to $20\%$ packet loss, the LSTM and GRU baselines suffered rapid catastrophic failure, managing an average TTF of only 92.9 and 106.8 steps respectively, as their discrete internal states became misaligned with the physical world. At $60\%$ packet loss, the LSTM baseline collapsed to a mere 50.0 steps. Conversely, the CfC maintained highly stable predictions across all degradation regimes, achieving an average TTF of 277.7 steps at $20\%$ loss and 257.3 steps at $60\%$ loss. To eliminate the possibility that this performance gap was merely an artifact of evaluating on Out-Of-Distribution (OOD) noise, we conducted an ablation study where the LSTM was trained using explicit data augmentation (injected with $20\%$ ZOH packet loss during optimization). Even when explicitly trained on lossy trajectories, the augmented LSTM only achieved an average TTF of 135.8 ($\pm 164.5$) steps at $20\%$ test loss, remaining vastly inferior to the zero-shot CfC. A non-parametric Mann-Whitney U test over the 30 seed runs confirms that the predictive superiority of the CfC over the LSTM at $20\%$ packet loss is statistically highly significant (raw $p = 1.2 \times 10^{-4}$, adjusted $p_{adj} < 0.001$ for $m=3$ comparisons via Holm-Bonferroni \cite{holm1979simple}, with a large effect size of $d \approx 1.41$ \cite{cohen1988statistical}), accounting for the heavy-tailed error distributions caused by catastrophic pendulum failures.

While the physical sensor input signal $I(t)$ strictly requires temporal imputation via a Zero-Order Hold (ZOH) mechanism to maintain dimensional consistency, the continuous-time CfC engine integrates the internal hidden state dynamics continuously without requiring auxiliary recurrent variables to track time. The physical time-delta is explicitly passed into the network's time-gate to dynamically scale the state update. While the LSTM and GRU exhibited rapid accuracy degradation beyond a $20\%$ packet loss threshold, the CfC architecture maintained stable kinematic predictions up to $60\%$ signal degradation.

To visually validate this resilience, Figure \ref{fig:timeseries_comparison} illustrates a qualitative time-series comparison of the predicted control force under a 60\% packet loss regime. As sensor frames are dropped, the discrete LSTM's internal state update misaligns with physical time, resulting in severe oscillatory deviation and instability. Conversely, the continuous-time CfC leverages the explicit temporal delta to smooth and interpolate the trajectory, remaining closely matched with the ground truth.

\subsection{Hardware-in-the-Loop Simulation with Real Sensor Jitter}
To verify the architecture's execution behavior under physical constraints, we conducted a Hardware-in-the-Loop (HIL) Simulation \cite{macchelli2023hardware}. Rather than a closed-loop physical CartPole (which is unobservable solely via an IMU), the ESP32-S3 was interfaced with a physical I2C MPU6050 acting as a hardware dummy load to generate real-world bus jitter and interrupt overhead. Simultaneously, the simulated CartPole states were sequentially injected into the embedded pipeline, while the CfC OmniEngine consumed this noisy telemetry to compute control signals. The physical execution confirmed the reliability of the XIP pipeline, successfully generating high-frequency PWM control signals to a motor driver without triggering watchdog resets or stack overflows. While this validates that the firmware is highly resilient to I2C interrupt latency, we acknowledge that this open-loop test does not evaluate closed-loop control robustness, which remains an avenue for future work.

\subsection{Hardware Efficiency: Memory, Latency, and Power}
As detailed in Table \ref{tab:hardware}, the Execute-in-Place architecture outperformed standard TinyML frameworks across all hardware metrics. The XIP engineering is primarily responsible for dropping the active tensor SRAM footprint. All 16.5~KB of FP32 model parameters reside explicitly in the mapped Flash memory (ROM), inherently trading SRAM consumption for expected data-cache (D-Cache) miss penalties during sequential matrix-vector access. However, because the ESP32-S3 features a minimum 32~KB D-Cache and the combined memory footprint (16.5~KB ROM + 6.1~KB SRAM activations) is under 23~KB, the entire model fits within the cache. Consequently, after the initial cold-start miss penalties on the first inference step, the steady-state cache hit ratio converges to ~100\%, effectively nullifying Flash latency overhead. Our engine statically allocates ~6.1~KB of SRAM to guarantee deterministic execution without fragmentation, exclusively utilized for intermediate activation buffers and transient states. Furthermore, the purely mathematical state footprint of the CfC kernel represents a mere $1.2$~KB for the defined $d_{model}=32$ dimensions, contrasting sharply with the $42.5$~KB dynamic arena required by TFLite Micro for the equivalent discrete LSTM. Additionally, stack memory profiling via FreeRTOS (\texttt{uxTaskGetStackHighWaterMark}) confirmed that the CfC inference loop consumes less than 800 bytes of stack depth, completely avoiding stack overflow risks during asynchronous sensor interrupts. 

Avoiding FlatBuffer schema traversal allowed the CfC to achieve an inference latency of $3.43$~ms/step. Oscilloscope tracing of the power profile revealed a brief dynamic peak of 60~mW during the initial Flash page load, rapidly stabilizing to a steady-state consumption of 52~mW during the matrix multiplication loop, compared to the TFLite LSTM's $105$~mW draw. For context, the measured idle baseline of the ESP32-S3 system was $38$~mW. 

To isolate the architectural contribution of continuous-time dynamics from engineering optimizations, we implemented a custom ``LSTM-XIP'' engine executing the same bare-metal payload. The LSTM-XIP required 6.1~KB of SRAM and achieved an inference latency of $6.15$~ms/step, consuming 65~mW. While the XIP engine significantly improved the LSTM's efficiency over TFLite Micro, the CfC still fundamentally outpaces it due to requiring fewer gate evaluations per step, while offering unmatched temporal resilience.

\subsection{Silicon Parity and the FP32 Advantage}
Unlike standard edge deployments that rely on INT8 Post-Training Quantization (PTQ) to fit within SRAM constraints, our XIP architecture allows the CfC continuous-time solver to execute entirely in FP32 format natively on the Xtensa LX7 cores. While quantization to INT8 effectively reduces the memory footprint, previous work suggests it can degrade the dynamic range required for continuous-time dynamics in complex control loops. By retaining full FP32 execution, we guarantee mathematical parity between the PyTorch training environment and the physical microcontroller ($MSE < 10^{-6}$), preserving the true temporal fidelity of the original equations without risking quantization-induced instability.

\subsection{Generalization to Unmodeled Dynamics}
\label{sec:generalization}
To address concerns that the fundamental CartPole task serves as an insufficient benchmark, we conducted an additional preliminary stress-test to decouple temporal robustness from strictly linear kinematics. We evaluated the CfC (pre-trained solely on ideal, frictionless data) in a complex testing environment featuring simulated cart and pole friction ($\mu_{cart}=0.1$, $\mu_{pole}=0.05$) alongside Gaussian sensor noise ($\sigma=0.01$). Despite facing extreme 20\% packet loss combined with unmodeled non-linear friction and sensor degradation—a true Out-Of-Distribution scenario—the CfC maintained an average TTF of 206.6 ($\pm 113.8$) steps. This demonstrates that the temporal extrapolation capability of continuous-time networks generalizes strongly beyond ideal kinematic conditions, validating its position as a stepping stone toward highly non-linear real-world robotics.

\section{Limitations}
While the Zero-Copy architecture demonstrates significant efficiency gains, several limitations should be acknowledged:
\begin{enumerate}
    \item \textbf{Baseline Framework Overhead.} Although we isolated the memory gains of our XIP engineering from the CfC mathematical advantages by including an LSTM-XIP baseline, extending native XIP optimization to all discrete RNN variants (e.g., GRU) remains for future work.
    \item \textbf{Scalability ceiling.} Direct execution from external SPI Flash exposes the system to potential cache miss penalties. The ESP32-S3 possesses a relatively small Data Cache (32~KB / 64~KB). While 4,000-parameter models run efficiently, a model exceeding 50,000 parameters requires over 200~KB in FP32 format. This severely overflows the D-Cache, causing massive \textit{cache thrashing} as weights are constantly reloaded from the SPI Flash at each inference step, degrading latency non-linearly.
    \item \textbf{Task complexity.} While 30 random initialization seeds provide rigorous statistical confidence on the CartPole environment, expanding evaluation to higher-dimensional physical benchmarks (e.g., multi-axis drone stabilization) is necessary to map the scalability boundary of the CfC solver.
    \item \textbf{Extreme Jitter Saturation.} While the CfC successfully interpolates moderate packet loss, there is an unanalyzed theoretical limit as $\Delta t \to \infty$. If $N$ consecutive packets are lost such that $\Delta t \gg \tau$ (the learned time-constant), the time-gate will fully saturate. In this extreme regime, the network state decays exponentially to the learned steady-state bias $A$, guaranteeing stability but yielding a neutral prediction. Future work must mathematically map this saturation boundary for safety-critical control loops.
\end{enumerate}

\section{Conclusion and Future Work}
This paper demonstrates that Closed-form Continuous-time (CfC) networks are highly practical for severely constrained embedded systems. Leveraging Zero-Copy memory semantics allows engineers to deploy robust architectures with unmatched temporal resilience and energy efficiency. 

Future work will focus on two key areas: First, we plan to package the C++ OmniEngine as a micro-ROS node, enabling seamless integration with standard robotics middleware. This will allow the neural network to directly publish kinematic control states to widely used flight controllers (e.g., PX4 or ArduPilot) without breaking the zero-copy memory chain. 

Second, we will conduct ablation studies on scalability to determine the upper parameter boundary before the SPI Flash bandwidth is saturated by cache misses, ultimately defining the structural limits of Zero-Copy TinyML architectures.
